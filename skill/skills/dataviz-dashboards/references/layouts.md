# Макеты дашбордов (шпаргалка, пост 223)

## 1. Верхнеуровневый 👔
Для руководителей и базового взгляда на метрики. Правило: **от общего к частному** (сверху вниз).
Фильтров минимум или нет.

```
┌──────────┬──────────┬──────────┐
│  KPI 1   │  KPI 2   │  KPI 3   │   ключевые показатели и цели
├──────────┴──────────┴──────────┤
│            Динамика            │   динамика ключевых метрик
├────────────────────────────────┤
│            Разрезы             │   при необходимости: регион, категория, источник, платформа
└────────────────────────────────┘
```

**KPI-карточка:** название метрики слева вверху, период справа вверху; крупно `Fact` и `Plan`;
под ними мелко `vs plan` (%) и `WoW` (стрелка + %). `vs plan` ≥100% — зелёный, <100% — красный;
падение WoW — красный со стрелкой ↓ (если рост метрики — хорошо). Можно добавить спарклайн
с подписью последней точки (169). Все карточки одной структуры (169), каждая в своей рамке/фоне (159).

Пример: `Revenue | jul 26' — Fact 202.3m, Plan 215.4m, vs plan 94%, WoW ↓-4%`.
Ниже: «Revenue dynamics» (столбцы, один цвет), «Revenue split by city» (линии, 3 города).

## 2. Операционный ⚙️
Для самостоятельного анализа: много интерактива и метрик.

```
┌────────────────────────────────┐
│       Множество фильтров       │   2 ряда; дата + split by первыми
├──────────┬──────────┬──────────┤
│ Метрика 1│ Метрика 2│ Метрика 3│   каждая с выбором разреза (split by)
│ в разрезе│ в разрезе│ в разрезе│
├──────────┴──────────┴──────────┤
│  Таблица для выгрузки          │   ЛУЧШЕ НА ОТДЕЛЬНОЙ ВКЛАДКЕ
└────────────────────────────────┘
```

Пример фильтров: Date (`last 90 days`), Split by (`City`), Delivery type, Payment, Seller /
Segment, Buyer, Delivery service, Discount, Flag. Когда фильтров десятки — группировать в
контейнеры по смыслу («Признаки товара», «Признаки обращения», 159). Фильтр, относящийся к
одному графику, — внутри его карточки (155).

## 3. Для исследования 🔍
Временный: обычно нужен, чтобы заскринить графики в исследование или статью по A/B.
2 графика рядом, больше ничего. Никто не наведёт мышку → правила для скриншота:
- подсвечивать цветом главное: в A/B контроль серый, тест цветной; нужный разрез/период — цветом, остальное серым;
- обрезать лишние даты;
- в таблицах итогов рост зелёным, падение красным;
- подписывать оси и значения.

## 4. Слайд для синка (230, 231)
Слайд на экране пару минут, тултипов нет, в комнате и «графиковые», и «табличные» люди.
- Слева линии за несколько недель (тренд), легенда убрана, на конце каждой линии: категория, значение последней недели, WoW в цвете.
- Справа таблица по 3 неделям, отсортированная по WoW; WoW окрашен по смыслу (рост возвратов — красный).
- Заголовок с единицей: «Возвраты по категориям, шт».
- Собирать кодом из BI (python), а не скриншотами.

## Общие правила раскладки
- Блоки одной темы — под общим заголовком и рядом (близость, 155).
- Одна категория — один цвет на всём дашборде, в карточках и в динамике (84, 169).
- Схожие метрики — одинаковым типом графика (169).
- Важное вверху и слева; вспомогательное — ниже или на отдельной вкладке.
