# Выбор графика

Сначала вопрос, потом форма: «прежде чем строить визуализацию, спросите себя: что я хочу
сказать? Ответ подскажет нужный тип графика» (179).

## Один набор данных — разные вопросы (179)

| Вопрос | График | Цена |
|---|---|---|
| Какой период лучше/хуже, сравнить между собой | вертикальный барчарт | — |
| Куда движется метрика | линия | — |
| Насколько сильно изменилась | линия не от нуля | легко преувеличить масштаб изменений; подписывать, что ось не от нуля |
| Объём, «денежная масса» | area-чарт | закрашенная площадь «весит» |
| Кто лидер, кто аутсайдер | горизонтальный барчарт с сортировкой | хронология теряется |
| Точные значения + лидеры | таблица с условным форматированием | — |

## Частые ловушки

**Линия между категориями** → псевдодинамика. Категории сравнивать барчартами (46).

**Воронка vs водопад** (163). Воронка — только когда на каждом шаге становится меньше
(открытие → просмотр → корзина → оплата → получение). Начисления/списания/сгорания/остаток —
это изменение баланса → waterfall. Воронка-картинка, не отражающая данные, — ошибка вдвойне.

**Pie chart** (83). Подходит, когда категорий мало (≈4) и они сильно различаются. Ломается
на длинных названиях в легенде и маленьком размере — тогда горизонтальный барчарт.

**Двойные оси.** По умолчанию избегать — усложняют считывание (46). Исключение (127):
метрика-отношение + её числитель и знаменатель. Конверсия линией на одной оси, area
созданных и оплаченных заказов на второй — сразу видно, почему конверсия падает (оплаченные
стабильны, созданные растут).

**Несколько метрик на одном барчарте.** Лучше несколько горизонтальных барчартов рядом:
главная доля (с подсветкой невыполненного таргета) → абсолютное число (масштаб проблемы) →
вспомогательный объём (46). Для сравнения людей/команд по трём метрикам — по три
горизонтальных барчарта (134).

**Спагетти** — линейный график с 7–10+ линиями (135).
- Операционный дашборд с фильтром — допустимо.
- Статичная картинка/слайд — нет. Неважные линии → в «другое» или серым, важные — цветом.
- Кнопка «показать пики»: SQL с `lag` отбирает линии с сильным ростом к предыдущему дню, график превращается в несколько линий (135).
- Для слайда: подписать каждую линию на конце (категория, значение последней недели, WoW) вместо легенды и тултипа + таблица справа, отсортированная по WoW, красный/зелёный по знаку (231).

**Очень разный масштаб** (174). Топ-5 городов по 1000+ заказов в день, остальные ~100 —
маленькие прижаты к оси. Разделить на два подграфика (крупные / мелкие). Подписать, что шкалы
разные и сравнивать подграфики между собой нельзя.

**Созревающие метрики** (199). Метрики, которые «добираются» со временем (отзывы ~месяц,
retention), за свежий период занижены. Варианты:
1. Недозревшую часть линии — пунктиром или светлее.
2. Отделить недозревший период вертикальной линией.
3. В таблице (особенно retention-когорты) — недозревшие когорты светлыми цифрами.
4. Если есть прогноз — доверительный интервал.

**Таблица вместо графиков.** Когда нужно сравнить много сущностей по многим значениям
(рейтинги сериалов по сезонам), условно отформатированная таблица лучше барчартов (47).

## Дашборд ≠ арт

Сложные графики с большими легендами и необычными формами — для челленджей, статей и
пет-проектов, не для рабочих дашбордов: на работе нет времени разбираться в логике (134).
Тематические элементы (стаканчики, апельсинки, звёздочки рейтинга) уместны в инфографике
(22), не в дашборде.
